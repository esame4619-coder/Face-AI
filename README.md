# المحترف في AI

تطبيق Android عربي وخادم معالجة مفتوح المصدر. لا يعتمد الكود على API مدفوع.

## بنية مجموعة المعالجة (Worker Pool)

التطبيق يتصل بخادم مدير (Manager). عند تفعيل مجموعة العمال، يوزّع المدير طلبات تبديل الوجوه على عمال FaceFusion مستقلين:
- فحص صحة العامل قبل إرسال المهمة.
- اختيار متناوب Round-robin.
- تخطي العامل غير المتاح أو الذي استنفد حصته اليومية المعرّفة.
- التحويل التلقائي إلى العامل التالي، بحد أقصى 3 محاولات لكل طلب.
- طابور تزامن داخل المدير (حتى 4 عمليات توزيع متزامنة).
- تسجيل استخدام كل عامل يومياً في SQLite.
- نقطة `GET /pool/status` محمية بمفتاح API لعرض حالة العمال والحصص.

### إعداد المدير

صورة المدير الخفيفة: `backend/Dockerfile.manager`؛ لا تحتاج إلى تنزيل FaceFusion. إعدادات النشر التفصيلية في [`backend/DEPLOYMENT.md`](backend/DEPLOYMENT.md). صورة العامل هي `backend/Dockerfile` وتشمل محرك FaceFusion.

اضبط متغير البيئة `WORKERS_JSON` على المدير فقط. مثال توضيحي؛ استبدل الروابط بمضيفين تملك حق تشغيلهم فعلياً:

```json
[
  {
    "name": "worker-1",
    "url": "https://worker-one.example",
    "api_key": "WORKER_ONE_SECRET",
    "daily_jobs": 20
  },
  {
    "name": "worker-2",
    "url": "https://worker-two.example",
    "api_key": "WORKER_TWO_SECRET",
    "daily_jobs": 15
  }
]
```

- `daily_jobs` حد محلي يطبقه المدير لكل عامل في اليوم UTC؛ القيمة 0 تعني عدم وضع حد محلي، ولا تعني أن مزود الاستضافة يسمح باستخدام غير محدود.
- ضع `API_KEY` على كل عامل كـSecret، واجعل قيمة `api_key` المقابلة مطابقة له.
- اضبط `API_KEY` على المدير، وأدخل المفتاح نفسه في إعدادات التطبيق. هذا المفتاح منفصل عن مفاتيح العمال.
- اضبط `POOL_DB_PATH` على مجلد دائم التخزين في المدير؛ الافتراضي `/data/worker_pool.sqlite3`.
- لا تضع الأسرار في Git أو ملفات التطبيق أو رسائل المحادثة.

كل عامل يشغّل نفس Backend وFaceFusion محلياً، لكن دون ضبط `WORKERS_JSON` عليه؛ بذلك ينفذ المهمة محلياً بدلاً من إعادة توجيهها.

### نقاط API

- `GET /` حالة الخدمة.
- `GET /health` حالة المحرك.
- `GET /pool/status` حالة العمال والحصص (يتطلب Bearer API key).
- `POST /api/faceswap` ملفا `source` و`target`.
- `POST /api/enhance` ملف `image` (تحسين أساسي بـPillow وليس AI Super Resolution).

## النشر المجاني والقيود الواقعية

الكود الآن يحتوي على مدير توزيع وتحويل تلقائي، لكنه لا ينشئ حسابات استضافة ولا يوفّر موارد GPU بنفسه. يجب تسجيل كل عامل بعد نشره يدوياً على مضيف يسمح فعلاً بتشغيل Docker/FaceFusion. لا توجد حالياً قائمة مضيفين مجانيين موثّقين ومضمونين يعملون 24/7 أو يقدمون GPU يومياً بلا توقف؛ لذلك لا ندّعي أن مجموعة الخوادم أصبحت متاحة بعد.

Hugging Face أظهر في حساب المستخدم أن Docker وGradio يتطلبان خطة مدفوعة، لذلك لا نستخدمه ضمن المسار المجاني. كما أن حصص الخدمات المجانية قابلة للتغيير، وقد تتوقف أو تنام؛ لا يجوز تجاوز شروطها بإنشاء حسابات متعددة أو تدويرها للتحايل على الحدود.

## الحالة الفعلية للأدوات
- تبديل الوجوه في الصور: تم اختبار محرك FaceFusion فعليًا داخل Docker على CPU؛ يتطلب الاستخدام من الهاتف تشغيل خادم Colab مؤقت أو خادمك الخاص.
- تبديل الوجوه في الفيديو: مسار API ومعالجة موجودان، لكن اختبار تتبع الهوية عبر فيديوهات متعددة الأشخاص والاحتجاب ما زال مطلوبًا.
- تحسين الصور: عند تشغيل خادم Colab وتثبيت نموذج EDSR x2، ينفذ رفع دقة عصبي فعلي عبر OpenCV DNN؛ إذا لم يكن النموذج متاحاً يرجع التطبيق تلقائياً لتحسين Pillow الأساسي ويُظهر نوع المحرك المستخدم.
- تغيير الصوت: مؤثرات طبقة صوت فعلية عبر FFmpeg متصلة بالتطبيق، وليست استنساخ هوية صوت.
- استنساخ الصوت وصناعة الأغاني: ما زالا غير مفعّلين ويحتاجان محركات مستقلة.
- لا توجد خوادم GPU مجانية دائمة مؤكدة أو عمال معالجة مفعّلون في الإعداد الحالي.

## تغيير الصوت
- نقطة API: `POST /api/change-voice` مع الملف الصوتي والحقل `voice_type` (رجل/امرأة/طفل).
- يستخدم FFmpeg لتغيير طبقة الصوت مع الحفاظ التقريبي على المدة، ويتيح مؤثرات EQ لونية (مصري/خليجي/فصحى/أمريكي/بريطاني). هذه المؤثرات لا تغيّر اللغة أو اللهجة المنطوقة ولا تستنسخ هوية متحدث.
- هذا مؤثر صوتي تقليدي وليس استنساخًا لهوية متحدث أو تحويلًا عصبيًا.
- الحد الأقصى: 30 MB و10 دقائق. يحتاج ffmpeg وffprobe على خادم المعالجة.


## تشغيل خادم Colab المؤقت (CPU أو GPU)
يمكن فتح [دفتر Google Colab](https://github.com/esame4619-coder/Face-AI/blob/main/deploy/Face-AI-Colab-Temporary-Server.ipynb) وتشغيل الخلايا بالترتيب. إذا كان GPU متاحًا في الجلسة، يختار الدفتر FaceFusion CUDA ويتحقق من `CUDAExecutionProvider`؛ وإلا يستخدم CPU. بعد ظهور رابط Cloudflare المؤقت، أدخله مع المفتاح السري في إعدادات التطبيق. هذا عامل واحد مؤقت، والرابط والجلسة ينتهيان عند إيقاف Colab.

## واجهة تغيير الصوت
`POST /api/change-voice` يستقبل ملف `audio` والحقل `voice_type` بقيمة `رجل` أو `امرأة` أو `طفل`. يرجع ملف MP3 بعد تأثير تغيير طبقة الصوت باستخدام FFmpeg. هذه معالجة صوتية تقليدية وليست استنساخًا عصبيًا أو تقليدًا لهوية شخص.


## تحسين الصور بالذكاء الاصطناعي (EDSR x2)
دفتر Colab يثبت نموذج EDSR x2 المفتوح المصدر ويضعه في `/content/models/EDSR_x2.pb`. عند تشغيل الخادم، يعلن `GET /health` عن `ai_enhance_available=true` إذا كان النموذج صالحاً، ويرجع `POST /api/enhance` ترويسة `X-Enhancement-Engine: EDSR-x2`. إذا لم يتوفر النموذج أو فشل، يعمل تحسين Pillow الاحتياطي وتظهر الترويسة `Pillow-fallback`. تم وضع حد ذاكرة للمعالجة الكبيرة.
